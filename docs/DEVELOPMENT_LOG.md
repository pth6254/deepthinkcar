# 개발 기록

2026-11-24 ~ 25 작업을 문제와 해결 순으로 정리했습니다. 수치는 당시 녹화와 로그 기준입니다.

## 1. 기본 구현
- 차선 인식, PID, 안전 정지, 녹화, 학습, 시뮬레이터를 구현
- 시뮬레이터 OpenCV 모드: 5바퀴 무이탈, 20 FPS
- 조종: SSH 키보드 → 웹 대시보드로 확장

## 2. 하드웨어 문제
| 문제 | 원인 | 해결 |
|---|---|---|
| `cv2.VideoCapture`로 카메라가 안 열림 | 최신 OS는 libcamera 사용 | picamera2 사용 |
| 사진이 검음 | 렌즈 캡 | 제거 |
| 모터 무반응 | 처음 설계(ESC)와 실제 부품(L9110)이 다름 | L9110 GPIO 드라이버 구현 |
| 여전히 무반응, 모터 핀이 LOW로 잡힘 | HAT 고장 또는 장착 불량 | HAT 교체 |
| 녹화 파일 손상 | 전원 차단 시 디스크 미기록 | 약 2초마다 동기화 |

## 3. AI 모델
| 단계 | 결과 |
|---|---|
| 사진 118장으로 처음부터 학습 | 오른쪽으로 치우침, 데이터 부족 |
| 키트의 사전 학습 모델 | 추가 학습 없이 OpenCV 오차와 상관 0.97 |
| 파인튜닝 (학습 518장) | 시험 녹화를 뺀 실험에서 조향 오차 약 5.6° → 3.4~4.0° |
| ±45° 재학습 (학습 851장) | 시험 녹화 192장에서 5.5° → 2.3° |

오차는 OpenCV 조향과의 차이이며 주행 성공률이 아닙니다.

## 4. 급커브
| 발견한 문제 | 조치 | 결과 |
|---|---|---|
| 30° 한계에 닿은 채 이탈 | ±45°로 확대 | 두 번째 커브 통과 |
| 넘어온 왼쪽 테이프를 오른쪽으로 착각 | 직전 위치로 구분 | 녹화에서 해결 |
| 커브 감속이 거의 없음 (듀티 45% → 43%) | 듀티 범위와 속도 계산 변경 | 직선 37%, 커브 31% |
| AI가 급커브에서 핸들을 풂 | 보정과 유지 조건 추가 | 일부 개선 |
| 꺾인 모서리를 늦게 인식 | 모서리 감지 | 좌 모서리 통과 |
| U턴 전환이 늦고 일찍 풀림 | 반대 방향 연결, 종료 조건 강화 | 45° 유지까지 성공 |
| 45°로 유지해도 U턴 바깥으로 이탈 | 급커브에서만 ±60° | 한 번 돌아 나옴 (안쪽 차선을 밟음) |
| 둥근 좌 급커브에서 반복 이탈 | 난이도 속도, 한쪽 차선 보강, 가로지르는 테이프 추적 | 실차 검증 중 |

## 5. 배운 점
- **데이터 부족은 모델 교체보다 사전 학습 모델로** 먼저 해결했다.
- **AI 정답을 OpenCV가 붙이면** OpenCV의 실수를 함께 배운다.
- 조건의 기준값 근처에서 기능이 **켜졌다 꺼지는 것**이 이탈로 이어졌다. 유지 구간(히스테리시스)이 필요했다.
- 한 커브를 고치면 다른 커브가 나빠질 수 있어 **전체 녹화로 회귀 비교**했다.
- 인식이 맞아도 **회전 반경**은 소프트웨어로 해결되지 않는다.
